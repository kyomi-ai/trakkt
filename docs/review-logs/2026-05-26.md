## Minor Issues (Nice to Have)

### 1. `is_dark_color` re-exported at crate root unnecessarily

`mod.rs` line 61 re-exports `is_dark_color` as a public item at the crate root:

```rust
pub use label_badge::{LabelBadge, is_dark_color};
```

The only internal consumer is `team_key_badge.rs`, which correctly imports via the direct
module path (`use super::label_badge::is_dark_color`) — not via the crate root re-export.
No external callers were found. Leaking a low-level luminance helper into the crate's public
API surface adds noise. If no external consumer needs it, remove it from the `pub use`
statement:

```rust
pub use label_badge::LabelBadge;
```

`team_key_badge.rs` does not need to change — it already uses the direct path.

### 2. Fallback color `#6B7280` disagrees with `DEFAULT_ICON_COLOR`

`project_detail.rs` line 1413 falls back to `"#6B7280"` (Tailwind gray-500) when the team
has no `icon_color`:

```rust
.unwrap_or_else(|| "#6B7280".to_string())
```

`team_icon.rs` defines `DEFAULT_ICON_COLOR: &str = "#3B82F6"` (blue) and uses it as the
fallback in the same scenario. The two fallbacks produce visually different badges for teams
without a color configured. Consider using `team_icon::DEFAULT_ICON_COLOR` for consistency,
or extracting a shared constant that both callsites reference.

## Positive Observations

**All pass-1 findings resolved correctly.** The component extraction is clean — `TeamKeyBadge`
owns the pill rendering and contrast logic, the caller only passes `team_key` and `color`.
The `super::label_badge::is_dark_color` import (rather than re-implementing the formula) is
exactly the right approach.

**`text-foreground` fix is complete and correct.** Both `LabelBadge` and `TeamKeyBadge` now
use the design token for light-background text. Dark mode will work correctly.

**`text-xs` replaces the arbitrary `text-[10px]`.** The badge now aligns with the type scale
and matches `LabelBadge`'s size, giving the row visual consistency between team and label
pills.

**Component styling is properly encapsulated.** The caller in `ProjectIssueRow` passes only
`team_key` and `color`; no Tailwind classes are leaked into the callsite.

**`shrink-0` on `TeamKeyBadge` is correct** and was not present on `LabelBadge`. This
prevents the pill from collapsing in flex rows with long issue titles — a thoughtful addition
for the project-detail context.
