**Notes**: `GET /api/v1/teams/{team_id}/icon` previously took no `AuthUser` and no workspace scope, so any caller holding a team UUID could fetch that team's uploaded icon bytes. This PR brings it in line with its already-authenticated, workspace-scoped siblings `upload_icon`/`delete_icon`.

Verified both enforcement layers are real, not cosmetic:
- Handler (`apps/server/src/routes/team_icon.rs:155-172`): `get_icon` now takes `auth: AuthUser`, resolves the team via `get_team`, 403s if `auth.workspace.workspace_id != team.workspace_id`, and passes `team.workspace_id` into `get_team_icon_data`.
- Service (`crates/trakkt-auth/src/team_service.rs:632-658`): `get_team_icon_data` gained a `workspace_id: &str` param; the SQL is `WHERE team_id = $1 AND workspace_id = $2` (not appended after the fact — replaces the old unscoped query), and a team that exists but belongs to a different workspace now returns `Err(NotFound)` rather than the row.
